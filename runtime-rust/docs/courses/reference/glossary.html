Shared vocabularyGlossary

The words both courses lean on. Skim it once; come back when a term bites. Compiler terms first, then runtime, then CI.

1Compiler & language

TermMeaning
SkyAn Elm-family, pure-functional language. Source files end in .sky. Compiles to typed Go (the reference backend) and — on this fork — to Rust.
Backend / targetThe thing the compiler emits. --backend go (default) or --backend rust. (Distinct from --target, which is the cross-compile triple like x86_64-unknown-linux-musl.)
Token streamThe flat list of lexical pieces (keywords, identifiers, literals, layout markers) the lexer produces from raw text, before structure is recovered.
ASTAbstract Syntax Tree — the program as a tree of nodes (a definition holds an expression holds a call holds arguments…). Sky has several: source, canonical.
Source ASTThe tree straight out of the parser — names are still unresolved (a bare println, not yet "the Log kernel"). Type Sky.AST.Source.Module.
CanonicalisationName resolution. Turns the source AST into the canonical AST where every name is qualified: a call is a VarKernel, a VarTopLevel, or a local. Function canonicaliseWithDeps.
Canonical ASTThe resolved tree codegen actually walks. Type Sky.AST.Canonical (a.k.a. Can.*). Nodes you'll meet: Can.Call, Can.VarKernel, Can.Binop, Can.Int, Can.Def.
HM type inferenceHindley–Milner — the algorithm that infers a type for every expression without you writing annotations. Sky's solver lives in Sky.Type.Solve; it produces SolvedTypes.
SolvedTypesThe solver's output codegen consumes: an environment (name → type) plus region types (a source location → the type inferred there). Lets codegen pick the right Rust type at each spot.
LoweringTranslating a higher-level form into a lower-level one. Here: canonical AST → Rust source strings. The Builder modules do the lowering.
KernelA built-in stdlib operation backed by a hand-written runtime function — e.g. String.fromInt, println, List.map. The compiler routes a kernel call to its Rust runtime fn.
Kernel routingThe map from a Sky kernel (module, name) to a Rust runtime function name. The single source of truth is kernelToRust in Builder/Kernel.hs (e.g. ("String","fromInt") → "string_from_int").
ShapeThe kind of program an example is, by how it runs: cli, server (HTTP), live (Sky.Live web UI), tui (terminal UI), webview (desktop). Each shape lowers a bit differently and is verified differently.
TaskSky's effect type, Task Error a. Every observable side effect returns one. In Rust it becomes SkyTask<E, A>, an async future executed at the program entry via block_on.

2The Builder modules (src/Sky/Generate/Rust/Builder/)

ModuleOwns
ModuleEmitter.hsTop level. buildProgram drives every module; buildModule turns a module's declarations into Rust items; detects main and whether it returns a Task.
ExprEmitter.hsThe biggest module. Turns one expression into a Rust string — exprToRustString / exprToRustInner handle calls, kernels, binops, closures, deferred effects.
Kernel.hsKernel routing — kernelToRust. The lookup table from Sky kernel to Rust runtime fn name.
TypeRenderer.hsRenders a Sky type as a Rust type string — typeToRustString (Int → i64, Task _ a → SkyTask<…>).
TypeEmitter.hsEmits Sky union/record definitions as Rust enums / structs.
Emitter.hsAssembles everything into the final main.rs + module files, and writes Cargo.toml — emitRust, emitCargoToml.
Naming.hsName mangling — toSnakeCase, moduleNameToRust, escaping Rust keywords.
Pattern.hsLowers patterns (a case arm, a destructuring param) to Rust match/param syntax.
Walker.hsPre-pass that scans the AST to collect metadata — which kernels are used (drives Cargo features), zero-arg defs, record shapes.
SigRegistry.hsHard-coded Rust signatures for known runtime fns — used to pin generic type params on a call.
Types.hsThe data structures: RustBuilder (accumulated output), EmitCtx (per-expression context), UsedKernels (feature gates).

3Runtime & build

TermMeaning
Runtime crateruntime-rust/src/sky_runtime/ — the hand-written Rust library every kernel call lands in (string.rs, log.rs, task.rs, db.rs, …). Copied into each generated project at build time.
Generated projectThe Rust crate the compiler writes to sky-out/rust/: main.rs + module files + Cargo.toml + a copy of the runtime + FFI bindings. cargo builds it into a binary.
Feature gateA Cargo feature that conditionally compiles part of the runtime. A CLI program doesn't pull in axum/sqlx — Walker.hs decides which features Emitter.hs turns on.
FFIForeign Function Interface — calling Rust crates from Sky. Sky's FFI is automatic: point sky.toml at a crate, the compiler reads its rustdoc JSON and generates bindings. Async/framework crates use a thin wrapper crate.
Equivalence (equiv)The correctness gate: the Rust build of an example must behave identically to the Go build (same stdout / HTTP body / browser scenario / TUI run), per its shape.

4CI (GitHub Actions)

TermMeaning
CIContinuous Integration — automatically building and testing your code on a server every time it changes, so breakage is caught immediately.
GitHub ActionsGitHub's built-in CI. You describe what to run in YAML files under .github/workflows/; GitHub runs them on its machines (runners).
WorkflowOne YAML file describing automation: when it runs (on:) and what it does (jobs:). This repo's is .github/workflows/examples-sweep.yml.
JobA unit of work that runs on one fresh runner. Jobs run in parallel unless one needs another. This repo has examples-sweep, examples-perf-sweep, static-perf, update-readme.
StepOne command or action inside a job, run in order. A step is either uses: (a prebuilt action) or run: (a shell command).
TriggerWhat starts a workflow: push, pull_request, workflow_dispatch (manual button), schedule (cron).
MatrixRun the same job many times with different inputs — here, the same sweep across ubuntu, macos, windows.
ArtifactA file a job uploads so later jobs (or you) can download it — here, the sweep result tables and perf TSVs.
CacheSaved files restored on the next run to avoid recompiling the world (the cargo target dir, the cabal store).
