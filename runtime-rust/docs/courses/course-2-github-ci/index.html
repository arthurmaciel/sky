Course 2 · from zero to confident GitHub CI — the Sky → Rust backend as a worked example

Continuous Integration sounds intimidating and is actually simple: a robot that builds and tests your code every time it changes. This course teaches CI from nothing, then uses this repo's real pipeline — a 3-OS sweep, perf benchmarks, and a README that updates itself — to take you all the way to modifying it yourself.

When you finish, you can…

  • explain what CI is and why every serious project uses it;
  • read and write GitHub Actions workflows — triggers, jobs, steps, matrices, caches, artifacts;
  • fully understand .github/workflows/examples-sweep.yml — the gating sweep, the dispatch-only perf/static jobs, and the self-updating README — and change it safely.

→Roadmap

Seven lessons, beginner-first. The early ones need no prior CI knowledge; the later ones dissect this repo's actual workflow. Lessons marked “soon” aren't written yet.

  • What is CI? (from zero) The problem CI solves, the vocabulary (runner, workflow, job, step), and what "green" means. ready
  • Your first workflow A 10-line .github/workflows/hello.yml — on:, jobs:, steps:, uses: vs run:. ready
  • Matrices, caching & artifacts Run across 3 OSes with a matrix; cache the cargo target; upload results as artifacts. The three workhorses of real CI. soon
  • Anatomy of examples-sweep.yml — the gating job The cornerstone: build + run + Go≡Rust equivalence across ubuntu/macos/windows. Why it's the gate, and how SKIP ≠ fail. soon
  • Dispatch-only jobs: perf & static-perf Why noisy benchmarks run on a button (workflow_dispatch) and a weekly schedule, never on every push. soon
  • The CI → README automation The update-readme job: writing back to the repo with contents: write, [skip ci], and the green-gate. soon
  • Modify it safely Add a job, change the matrix, add a check — and the guardrails that stop you breaking the gate or looping the auto-commit. soon
