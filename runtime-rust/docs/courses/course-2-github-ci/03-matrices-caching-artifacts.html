Lesson 3 · the three workhorses Matrices, caching & artifacts

Three features turn a toy workflow into real-world CI: a matrix (run everywhere), a cache (don't recompile the world), and artifacts (keep the results). This repo uses all three — let's learn them from its actual code.

1Matrix — run the same job many ways

You want the sweep on Linux and macOS and Windows. Instead of copy-pasting the job three times, declare a matrix and GitHub fans it out into one job per value:

.github/workflows/examples-sweep.yml (excerpt)

  examples-sweep:
    strategy:
      fail-fast: false                 # one OS failing doesn't cancel the others
      matrix:
        os: [ubuntu-latest, macos-latest, windows-latest]
    runs-on: ${{ matrix.os }}         # each run picks one OS from the matrix

That single block produces three parallel jobs. ${{ matrix.os }} is how a step reads "which value am I?" — used again to label uploaded results per-OS.

fail-fast: false By default, if one matrix job fails GitHub cancels the rest. For a cross-platform sweep you want the opposite — see all the failures at once, not just the first. So this repo turns fail-fast off.

2Cache — skip the expensive rebuild

Compiling Rust's dependency tree (tokio, axum, sqlx, serde) from scratch every run would take many minutes. The actions/cache action saves chosen folders after a run and restores them at the start of the next one:

      - name: Cache cargo target
        uses: actions/cache@v4
        with:
          path: |
            ~/.cargo/registry
            ${{ github.workspace }}/.cache/sky-rust-target
          key: ${{ runner.os }}-cargo-${{ hashFiles('runtime-rust/Cargo.lock', 'runtime-rust/Cargo.toml') }}
          restore-keys: ${{ runner.os }}-cargo-

The key is the heart of it. It includes a hash of the dependency files, so:

  • same deps → same key → exact cache hit → instant restore;
  • deps changed → new key → no exact hit, so restore-keys grabs the closest older cache as a warm starting point, and a fresh one is saved.
Cache the right thing Cache build outputs and downloaded packages (the cargo target dir, the registry, the cabal store) — never your source. And key on what actually changes the output (the lockfile). A key that's too broad serves stale builds; too narrow never hits. This repo also notes that sccache's GitHub backend is retired, so on CI it relies on actions/cache alone.

3Artifacts — keep the results

A runner is destroyed when its job ends. To keep anything — a results table, a log, a built binary — a job uploads it as an artifact:

      - name: Upload sweep scoreboard
        if: always()                       # upload even if the sweep failed
        uses: actions/upload-artifact@v4
        with:
          name: examples-sweep-${{ matrix.os }}   # one artifact per OS
          path: |
            ~/.cache/sky/examples-sweep/sweep-*.table
            ~/.cache/sky/examples-sweep/*.log
          if-no-files-found: warn

You can download artifacts from the run's page — and, crucially, another job can download them too. That's exactly how this repo's README-updater (Lesson 6) gets the perf numbers a different job measured.

if: always() The sweep step exits non-zero when an example fails — which would normally skip later steps. if: always() forces the upload to run anyway, so a failed run still gives you the table that shows what broke. Diagnosing CI is impossible without this habit.

4One more: don't waste runners

If you push twice quickly, the first run is now pointless. A concurrency group cancels the in-flight run for the same branch:

concurrency:
  group: examples-sweep-${{ github.ref }}
  cancel-in-progress: true

5Putting it together

You can now read the structure of this repo's main job end to end: a 3-OS matrix, each runner restores a cache, runs the sweep, and uploads its results as a per-OS artifact — with concurrency trimming redundant runs. Lesson 4 reads what that sweep step actually checks.

1. Why does this repo set fail-fast: false on its matrix?
2. What goes in a cache key so changed dependencies get a fresh cache?
3. Why if: always() on the artifact upload?

Summary

  • Matrix: one job × N values (3 OSes here). ${{ matrix.os }} reads the value; fail-fast: false shows all failures.
  • Cache: actions/cache saves/restores build outputs, keyed on a hash of the lockfile (+ restore-keys for a warm fallback).
  • Artifacts: upload-artifact keeps results past the runner's life; another job can download-artifact them. Use if: always().
  • Concurrency cancels superseded runs on the same branch.
