Lesson 5 · the lookup table How a Sky call becomes a Rust function

When codegen meets a kernel call like String.fromInt, it has to know the exact Rust function to emit. That decision lives in one place: kernelToRust in Builder/Kernel.hs. This lesson opens it, including the fallbacks and the corner cases that bite.

1The core: a big lookup function

kernelToRust takes the module and the name and returns a Rust function name. It's a long pattern-match — the single source of truth for the whole stdlib:

src/Sky/Generate/Rust/Builder/Kernel.hs

kernelToRust :: String -> String -> String
kernelToRust mod name = case (mod, name) of
    ("String", "fromInt")        -> "string_from_int"
    ("List",   "map")            -> "list_map_consume"
    ("Dict",   "empty")          -> "dict_empty"
    ("Task",   "succeed")        -> "task_succeed"
    ("Task",   "andThen")        -> "task_and_then"
    ("Task",   "run")            -> "task_run"
    -- …hundreds of arms…
Why a hand-written table? The Rust function name isn't always a mechanical transform of the Sky name — List.map maps to list_map_consume (the Rust fn takes ownership of its list), and acronyms like formatHTTP need care that automatic snake-casing gets wrong. An explicit table lets each kernel name its exact runtime counterpart, with a comment when it's surprising.

2Short names and qualified names

The same kernel can arrive named two ways depending on imports — String or the fully-qualified Sky.Core.String. The table lists both forms pointing at the same Rust fn:

("String",          "fromInt") -> "string_from_int"
("Sky.Core.String", "fromInt") -> "string_from_int"

3The fallbacks

Two catch-all arms at the very bottom handle anything not explicitly listed — this is how user FFI and new kernels still get a sensible name:

-- user FFI: a `Rust_`-prefixed module → drop the prefix, snake_case
_ | "Rust_" `isPrefixOf` mod -> toSnakeCase (drop 5 mod ++ "_" ++ name)

-- general fallback: dots → underscores, then snake_case the whole thing
_ -> toSnakeCase (map (\c -> if c == '.' then '_' else c) mod ++ "_" ++ name)

Real arms at Builder/Kernel.hs lines ~767–768. Snake-casing comes from Builder/Naming.hs.

4Two helpers around it

HelperJob
splitKernelNameSplits a combined name on the first underscore — "Decimal_fromInt" → ("Decimal", "fromInt") — so an Ffi.kernel "Decimal_fromInt" string can be routed.
kernelSigPrefixNormalises a module name for looking up a hard-coded signature (e.g. "List" → "Sky_Core_List"), used with SigRegistry to pin generics.

5The corner cases that bite

Corner case · special-cased in ExprEmitter A few kernels don't go through the plain "emit fn(args)" path because their shape is different — println joins its args with spaces; Task.andThen / Task.run inline a closure; a discarded let _ = someEffect must still run the effect (call task_run), not bind-and-drop it. These live in ExprEmitter.hs, using kernelToRust for the name but building the call by hand.
Corner case · VarKernel vs VarTopLevel A Sky stdlib function written in Sky as an Ffi.kernel alias arrives as VarTopLevel, not VarKernel. If a special-case in ExprEmitter only matches VarKernel, it silently misses the alias — and you get a "type-checks but cargo-fails" bug (e.g. the wrong type conversion is skipped). The rule, recorded in the project's learnings: any special-case arm must match both VarKernel and the matching VarTopLevel.
Corner case · zero-arg kernels Some kernels take no arguments — a constant like Math.pi, or Dict.empty. Walker.hs collects these so ExprEmitter emits them as a call dict_empty() rather than a bare value dict_empty. Getting this wrong produces a function pointer where a value was expected.

6Trace it once more

For String.fromInt (1 + 2): ExprEmitter sees Can.VarKernel "String" "fromInt", calls kernelToRust "String" "fromInt" → "string_from_int", and emits string_from_int((1 + 2)). That name resolves, at cargo build time, to the real pub fn string_from_int(i: i64) -> String in runtime-rust/src/sky_runtime/string.rs. The table is the bridge between the two worlds.

Summary

  • kernelToRust (module, name) → "rust_fn" is the single source of truth for stdlib routing; it lists both short and Sky.Core.* forms.
  • Two fallbacks handle user FFI (Rust_*) and anything unlisted (dots→underscores, snake_case).
  • Corner cases: ExprEmitter special-cases (println, Task.andThen, discarded effects); VarKernel vs VarTopLevel for Ffi.kernel aliases; zero-arg kernels emitted as fn().
