Lesson 2 · how it got here A history of the Sky → Rust backend, in eleven phases

Code makes more sense when you know why it grew the way it did. This is the backend's story, grouped into phases from the project's own dated log (runtime-rust/docs/PROGRESS.md). Read it once for the shape of the thing — later lessons revisit the pieces in depth.

How to read this Each phase is a problem the team hit and the thing they built to solve it. Notice the rhythm: build a capability → discover it's subtly wrong → add a regression test → fix the root cause. That loop is the project.

1Foundations — runtime & kernels

Before any Sky could become Rust, there had to be Rust to call. The first work was the runtime crate (runtime-rust/src/sky_runtime/) — hand-written Rust mirroring Go's standard library, function by function — and the kernel routing layer (Builder/Kernel.hs) that connects a Sky stdlib call to its Rust function.

~44 stdlib kernels (String / Path / Dict / File / Time / Random / Json) + the Set and Std.Db.Decode subsystems. PROGRESS: "44 stdlib kernels + Set + DbDec subsystem".

2The deferred-effect model

A deep correctness bug surfaced early: Sky's effects (logging, I/O, time) must run when the Task executes, not when it's constructed — that's how Go behaves. The Rust runtime was running them eagerly, so an example could print things in the wrong order or at the wrong time. Rewiring effects to defer into the Task body (and fixing Task.run) aligned Rust with Go and unblocked the first full pass of 37/37 examples green.

Commit 1ba0b764 — deferred-effect model + discarded-Task handling.

3The "known-limitations" sweep — green ≠ correct

Reaching 37/37 was a trap, not a finish line. The README's "Known limitations" list hid real codegen holes — programs that type-checked but failed to compile, and runtime panics. The team triaged and fixed eight in one sweep (List.sortBy, wildcard any fields, unconstrained Result payloads, withTransaction isolation, errorToString quoting, the Task.retryWith run-once bug, non-Clone task captures). Every fix shipped with a pre-failing regression fixture first.

Fixtures runtime-rust/tests/sky/{56..62}-*; commits incl. 283cae5d (retryWith), a6712e6b (errorToString).

The lesson behind the phase "Green build ≠ correct" recurs through the whole project. A passing example sweep can still hide a bug no example happens to exercise — so a fix isn't trusted until a test that failed before it now passes. You'll see this principle baked into the codegen and the CI.

4Multibackend entry

Some examples use more than one backend (e.g. Live and Tui in 24-tui-kitchen-sink). These broke with conflicting init signatures and Task.run type mismatches. The fix came from a written spec first: a backend's Task.run is the program entry, so drop the wrapper and derive the init shape from Sky's own types.

Spec 2026-06-12-rust-multibackend-entry-model.md.

5A modern webview stack

The desktop backend was stuck on an old wry/tao that wouldn't compile on current macOS/Windows and crashed on Linux. Migrating to wry 0.55 / tao 0.35 with per-OS branches unblocked the webview examples (29, 31) and the composite UI (38).

Commits abf3e92b (modern wry/tao), f8ba8e03 (CI deps).

6Static linking, cross-compilation & the allocator

Production wants small, portable binaries. The team added opt-in static binaries (Linux musl), cross-compilation (arm64, gnu), symbol stripping, and an allocator choice. A 2×2 benchmark (alloc-stress) proved mimalloc is ~1.7× faster than glibc and that musl's own malloc is a throughput cliff — so static builds default to mimalloc.

Commits bc97cfe7 (static + mimalloc), 55e22ad1 (strip). The 2×2 table lives in docs/TECHNICAL-DETAILS.md.

7Naming alignment: --target → --backend

The fork had overloaded --target onto two ideas — which backend (go/rust) and which OS/arch. That confused users and clashed with Rust tooling. The rename freed --target for the raw cross-compile triple (matching cargo --target) and added a migration guard. A pervasive but principled change — 69 fixtures, 12 Haskell files, CI, skills.

Commit b66c25ec.

8The DbDec subsystem

The missing core DB feature: decoding query rows into typed records. A design choice unified everything on one shared Decoder<E,T> (a DB row is decoded as JSON), reusing the JSON decoder machinery instead of building a second one — DbDec.string/int/money/nullable/map/andThen/map2–5 + SQL-gen kernels.

Spec 2026-06-16-dbdec-subsystem.md.

9The autoref/SkyStringify pitfall

A subtle, instructive bug: a generated trait impl that recurses into all fields needs every field type to implement that trait. Fixing errorToString with a SkyStringify trait broke every Std.Ui project (E0599) because the impl lived in an always-compiled module and the UI types (Element/Html/Color) didn't have it. Co-locating + feature-gating the impl fixed the whole class.

Commits adfc2afe, 0abe2e60; recorded as a CLAUDE.md learning.

10CI consolidation

Verification was scattered across four separate sweeps and was Linux-only. The team folded build + run + Go≡Rust equivalence into one cornerstone examples-sweep, on a 3-OS matrix, with night-gating and a per-OS result table. (Course 2 is all about this.)

Commits fbc19e83 (cross-platform CI), 22290857 (unified sweep); the lib/{examples,checks,env}.sh trio.

11Docs automation

The newest phase: the README kept going stale within hours of a sweep. The fix was a single-source-of-truth policy — machine-owned fenced tables written only by readme-tables.py from CI artifacts, a self-committing update-readme CI job, and deep internals split into docs/TECHNICAL-DETAILS.md.

Spec/plan 2026-06-18-readme-docs-overhaul; runtime-rust/scripts/readme-tables.py.

★The threads that run through all of it

  • No runtime panic from well-typed Sky. The reason the backend exists — soundness by construction, not by catching.
  • Green build ≠ correct. Every fix earns a pre-failing regression test; real third-party projects are the strongest proof.
  • Single source of truth. Humans edit prose; machines write data tables; history lives in PROGRESS.md.
  • Design first. The hard phases (multibackend, webview, static, DbDec) each began with a written spec.
  • Boundary discipline. Fork edits stay inside runtime-rust/, the Rust codegen, and examples/rust/ — never the shared stdlib or the Go backend.
