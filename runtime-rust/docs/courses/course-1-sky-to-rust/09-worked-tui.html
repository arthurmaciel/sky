Lesson 9 · TEA in the terminal Worked shape — Sky.Tui ×2

By now the pattern should feel inevitable. Sky.Tui is the same TEA again — in a terminal. The only new piece is onKey (keyboard events) and an entry kernel tui_app. Short lesson; you already know the rest.

AExample 1 — 21-tui-stopwatch

examples/21-tui-stopwatch/src/Main.sky (trimmed)

init : () -> ( Model, Cmd Msg )
update : Msg -> Model -> ( Model, Cmd Msg )
view : Model -> String
subscriptions model = -- Sub.every 100 Tick when running
onKey : KeyEvent -> Msg

main =
    Tui.app
        { init = init, update = update, view = view
        , subscriptions = subscriptions, onKey = onKey }

The emitted entry

examples/21-tui-stopwatch/sky-out/Rust/src/main.rs (real, trimmed)

pub fn main_view(model: MainModel) -> String { … }

pub fn sky_main() -> SkyTask<()> {
    tui_app(main_init, main_update, main_view, main_subscriptions, /* onKey */)
}

fn main() { match block_on(sky_main()) { … } }

That's the whole story:

  • Tui.app → tui_app(init, update, view, subscriptions, onKey) — the same five TEA functions, plus the key handler.
  • This stopwatch's view returns a plain String (a text TUI), so main_view -> String. (A richer TUI returns a Std.Ui Element, which the Tui runtime renders to ANSI cells.)
  • subscriptions uses Sub.every 100 Tick → a sub_every kernel that fires a Msg on a timer.
  • Bare Task entry → block_on (which puts the terminal in raw mode, runs the loop, restores it on exit).

BExample 2 — 23-tui-todo

A to-do TUI: add, toggle, delete items with the keyboard. More state and more onKey arms, but identical machinery — type Msg → enum, Model (a list of items) → struct with a Vec, update → match, list operations → the list_* kernels from Lesson 5. Its main is the same Tui.app { … } → tui_app(…) entry.

CThe Tui pattern, generalised

  • TEA as always: Msg→enum, Model→struct, update→match.
  • view → String (text) or → Element (Std.Ui, rendered to ANSI cells).
  • Tui.app { …, onKey } → tui_app(init, update, view, subscriptions, onKey); bare Task → block_on entry that manages the terminal.

Summary

  • Sky.Tui = TEA in the terminal: Tui.app{…, onKey} → tui_app(init, update, view, subscriptions, onKey), bare-Task block_on entry.
  • view → String (text) or Element (Std.Ui → ANSI).
  • Live vs Tui differ only in entry kernel, view output, and routes-vs-onKey; everything else is identical TEA.
