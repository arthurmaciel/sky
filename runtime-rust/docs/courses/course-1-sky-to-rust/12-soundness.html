Lesson 12 · the whole point Soundness: "no panic from well-typed Sky"

Everything in this course serves one promise: a well-typed Sky program must never trigger a runtime crash in the generated Rust. Not "rarely". Never. This final lesson explains why that's the reason the Rust backend exists — and the corner cases it designs out to keep the promise.

1The existential rule

If it compiles, it works A well-typed Sky program must not be able to trigger a panic, an unwrap/expect failure, an unchecked downcast, an out-of-bounds index, or any other runtime abort — in the generated Rust or the runtime crate. This isn't aspirational; it's the product. "It type-checks, so it builds, so it works" is a chain the whole pipeline exists to make true.

2Statically total, not caught-at-runtime

There are two ways to deal with the things that can go wrong. Sky's Go backend leans on the dynamic one; the Rust backend insists on the static one.

So in generated Rust and the runtime's Sky-reachable paths, the project treats .unwrap(), .expect(), panic!, [i] indexing, and unchecked downcast as bugs to fix at the root. An invariant that "can't fail" still uses a total form — if let, match, .get() — with a structured-error fallback.

The one panic you saw — and why it's allowed In the worked lessons you spotted an ffi_kernel_polyfill that panic!s. That's a compiler-bug contract, not a Sky-reachable path: it only fires if codegen itself produced something impossible. Well-typed Sky can never reach it. The rule isn't "zero panic! tokens" — it's "no panic reachable from well-typed Sky".

3Designing out dynamism (the hard part)

The interesting cases are where a Sky feature is dynamically typed at the language level — pub/sub payloads, FFI any, JSON values. The tempting move is to erase the type, downcast later, and hope. The project's rule:

Mirroring Go's reflect/any risk is a defect, not parity Instead of erase-and-downcast, use the concrete types the type-checker already knows at each call site to monomorphise the dynamism away. The pub/sub broker, for example, is keyed by TypeId into per-type channels, so a payload travels as its real type T and is never downcast. Any residual dyn Any must be provably correct by construction — keyed so the one cast can't fail — never payload-dependent.

4When something genuinely can't be caught at compile time

A few mismatches the Sky type system can't see — say a publisher and a subscriber that disagree on a topic's payload type. The rule there is equally strict: degrade gracefully — drop the message and emit a structured warning — never panic. Graceful degradation, not a crash, is the floor for the rare unprovable case.

5How the promise is kept honest

A promise this strong needs enforcement, which is the "green ≠ correct" thread from Lesson 2 turned into practice:

  • Every fix earns a pre-failing regression test. The failing test is the discovery artifact; the fix isn't trusted until that test passes.
  • The equivalence sweep (Course 2, Lesson 4) runs each example and compares to Go — catching behavioural bugs a build can't.
  • Real third-party projects are the strongest proof — they exercise code shapes no example happens to.
  • "Type-checks but cargo-fails" is a tracked bug class, not an acceptable state — the whole point is that type-checking implies building implies working.

★The course, in one sentence

The front end (parse → canonicalise → type-solve) removes every ambiguity, so codegen can lower a fully-known program into Rust that calls a hand-written, total runtime — and the result is a native binary where, if it compiled, it works. That sentence is the whole pipeline, and now you can defend every clause of it.

Summary — and Course 1 complete 🎉

  • The promise: no runtime panic reachable from well-typed Sky — the reason the Rust backend exists.
  • Strategy: statically total (design the failure out), not reflect+recover. unwrap/panic!/unchecked-downcast in Sky-reachable code are bugs.
  • Dynamism is monomorphised away (TypeId-keyed broker); residual dyn Any is correct-by-construction; unprovable mismatches degrade gracefully, never crash.
  • Kept honest by pre-failing regression tests, the equivalence sweep, and real-app proof-tests — "green ≠ correct" in practice.
