## Gaps by subsystem

### live-core (Sky.Live runtime: session lifecycle, stores, SSE, routing, history, head injection, input preservation, status banner)

**How Go works:** A GET hits `handleInitial` (live.go:3637): `sessionIDNamed` reads the base-path-aware cookie (`cookieName`, default `sky_sid`) with a `MaxAge=sessionTTL` so it survives browser restart; on miss it mints a fresh 256-bit URL-safe-base64 sid (`generateSkySessionID`, live_store.go:1039) and calls `init(req)`. `chooseStore` (live_store.go:980) builds memory/sqlite/postgres/redis backends (no firestore case despite docs). Each store keeps a live `*liveSession` plus a serialized model checkpoint; a returning cookie on a different replica/restart re-hydrates cold. The page wrap (live.go:3801) splices `renderAppHead(app.head, model)` into `<head>`, the dev banner, and `liveJSWithCfgAndCsrfWithBase` (banner strings templated from env + `cfg.status` overrides via `resolveBannerStrings`). `handleEvent` runs the optional `guard` (live.go:4361) — a reject sets Notification/NotificationType on the model and skips `update` — then dispatches; it reconciles client-posted `inputSeqs` and replies `{seq, ackInputs, patches}` (writeEventJSON) plus header acks so the client retires dirty uncontrolled inputs. `handleSSE` (live.go:5434) sends ~2KB padding, a `hello` frame carrying `{v,sid,ts}`, a 15s heartbeat, X-Accel-Buffering:no, AND a full-body reconnect-resync frame (live.go:5498) so a restored/redeployed session repaints. Routing (`matchRoute`/`applyRouteWithParams`) matches in declaration order, captures `:param`, and `onNavigate` fires a Msg after each route change. `api`/`staticDir` serve REST handlers + static files alongside Live pages.

**How Rust works:** `live_app`/`live_app_routed` (live/mod.rs:667,709) mount an axum router. The `page` handler reads the base-path-aware cookie (`sid_from_cookie`), on a store hit re-applies routing and re-renders, on a cold hit hydrates a fresh driver, on a miss builds a `LiveReq` and calls `init(req)` minting a fresh 128-bit hex sid (`new_sid`, mod.rs:522). `choose_store` (store.rs:372) supports memory/sqlite/postgres/redis (feature-gated; no firestore). `page_response` sets `{name}={sid}; Path; HttpOnly; SameSite=Lax[; Secure]` with NO MaxAge. The per-session driver (`drive_session`) folds Msgs through `update`, diffs, and pushes `patches` frames over SSE; `event_handler` (mod.rs:961) decodes `{sessionId,handlerId,id,event,msg,args}`, resolves the handler, enqueues the Msg, and replies `{"seq":N,"patches":[]}`. The `sse_handler` (mod.rs:887) emits 2KB padding, a `hello` frame with body `{}`, a 15s heartbeat, and X-Accel-Buffering:no. The browser client (client.js, ported near-verbatim) has full status-banner, watchdog, queue, data-sky-path, sky-nav, popstate, r.ok-gating, ackInputs-ingest, and reconnect-resync (`event: patch`) logic. Codegen (ExprEmitter.hs:1440) splices only init/update/view/subscriptions/routes/notFound from the `Live.app` cfg — head/guard/onNavigate/consoleAuth/api/staticDir/status are dropped.

#### [P0] SSE reconnect-resync full-body frame never sent by Rust server  ·  status: missing  ·  effort: M

- **Go behavior:** handleSSE re-renders the current view and writes it as a full-body `event: patch` frame on EVERY fresh SSE connection (live.go:5498-5560), so a binary restart / `sky watch` rebuild / deploy paired with a persistent store (sqlite/redis/postgres) repaints the browser DOM the moment SSE reattaches — subscriptions launched by the old process are gone, so without this nothing pushes until the user dispatches a Msg.
- **Gap:** Rust sse_handler sends hello + heartbeat only; it never emits the full-body resync frame. The Rust browser client HAS the `event: patch` listener (client.js:1355, comment explicitly names 'reconnect-resync') but the server never produces it. Result: after any restore-from-checkpoint (cold hit) or process restart, the cold-hydrated session's DOM stays frozen on whatever HTML the browser last had until a user-driven Msg happens to produce a diff. For a redeployed app with a sqlite/redis store this is a visibly stale UI — the exact scenario persistent stores exist to fix.
- **Go loc:** runtime-go/rt/live.go:5498 (reconnect-resync block); runtime-go/rt/live.go:5434 handleSSE
- **Rust loc (fix lands):** runtime-rust/src/sky_runtime/live/mod.rs:887 sse_handler (add resync after hello)
- **Fill approach:** In sse_handler, after sending the hello frame, lock the session entry, render the current `last_view` to HTML via render_html, and send a full-body frame `sse::frame("patch", &json)` where json is `{"seq":seq,"body":<html>}` (matching the client's legacy `event: patch` shape it already parses at client.js:1355). Recover from a view panic is unnecessary in Rust (total). Bump the session seq so the frame's seq is monotonic vs subsequent patches.

#### [P1] Server-side input preservation (inputSeqs / ackInputs) absent in Rust  ·  status: missing  ·  effort: L

- **Go behavior:** Go tracks per-input dirty seqs on the session (sess.inputSeqs, live.go:2119). handleEvent reconciles client-posted input seqs into the session (reconcileInputSeqs, live.go:2351) and every frame/reply carries `ackInputs` (ackInputsForPrevTree, live.go:2386) in the JSON body AND via header, so the client retires dirty flags and the next diff omits clobbering uncontrolled inputs (text/textarea/select values) during server-driven re-renders.
- **Gap:** Rust's EventBody (mod.rs:275) decodes only {sessionId,handlerId,id,event,msg,args} — it never reads the client's posted input seqs — and event_handler replies `{"seq":N,"patches":[]}` with NO `ackInputs` key and no X-Sky-Ack-Inputs header. The Rust client (client.js:90 __skyIngestSeq, :738) reads X-Sky-Ack-Inputs and parses response.ackInputs, but the server never supplies either, so the dirty-input retirement protocol degrades to client-only heuristics (__skyIsDirty). A fast input + concurrent Sub.every re-render can still clobber an in-flight uncontrolled field that Go would have protected via the server-authoritative ack.
- **Go loc:** runtime-go/rt/live.go:2351 reconcileInputSeqs; runtime-go/rt/live.go:2386 ackInputsForPrevTree; runtime-go/rt/live.go:2548 writeEventJSON
- **Rust loc (fix lands):** runtime-rust/src/sky_runtime/live/mod.rs:275 EventBody (add inputSeqs); runtime-rust/src/sky_runtime/live/mod.rs:961 event_handler (return ackInputs); runtime-rust/src/sky_runtime/live/mod.rs:248 SessionEntry (add input_seqs map)
- **Fill approach:** Add `input_seqs: HashMap<String,i64>` to SessionEntry; extend EventBody with `#[serde(default)] input_seqs: HashMap<String,i64>` (or a `state` array matching the client's POST shape); reconcile into the session on each event (retain max seq per id); compute the ack subset for ids present in the current tree (port ackInputsForPrevTree); include it as `"ackInputs":{...}` in the event_handler JSON reply and also set the X-Sky-Ack-Inputs / X-Sky-Seq headers the client already reads.

#### [P1] Live.app `guard` field dropped — no per-Msg authorization/validation gate  ·  status: missing  ·  effort: L

- **Go behavior:** When the cfg carries `guard : Msg -> Model -> Result Error ()` (also exposed on Tui.app), handleDispatch runs it BEFORE update (live.go:4361): an Err reason sets Notification/NotificationType=error on the model and short-circuits the dispatch (update is never called), logging a guard-rejected warning. This is the documented auth/permission gate for Live + Tui apps.
- **Gap:** The Rust codegen (ExprEmitter.hs:1440) splices only init/update/view/subscriptions/routes/notFound from the Live.app record; `guard` is silently ignored. live_app/live_app_routed have no guard parameter and drive_session calls update unconditionally. An app relying on guard for permission checks compiles to Rust with the gate entirely absent — a security-relevant behavioral divergence (the rejected Msg runs its full update on Rust).
- **Go loc:** runtime-go/rt/live.go:4361 guard dispatch; runtime-go/rt/live.go:2647 liveApp.guard field
- **Rust loc (fix lands):** src/Sky/Generate/Rust/Builder/ExprEmitter.hs:1440 (splice guard field); runtime-rust/src/sky_runtime/live/mod.rs:440 drive_session (call guard before update); runtime-rust/src/sky_runtime/live/mod.rs:667 live_app signature (add FGuard)
- **Fill approach:** Thread an optional `guard: Fn(Msg, Model) -> SkyResult<E,()>` through live_app/live_app_routed into LiveState; in drive_session, before update, run the guard and on Err set the model's notification fields (codegen must emit a RecordUpdate-equivalent) and skip update. Codegen: add a `guard` arm reading the cfg field, defaulting to a no-op closure when absent (row-poly: most apps omit it).

- **Go loc:** runtime-go/rt/live.go:3817 renderAppHead; runtime-go/rt/live.go:3800 page wrap headExtra splice
- **Rust loc (fix lands):** src/Sky/Generate/Rust/Builder/ExprEmitter.hs:1440 (splice head field); runtime-rust/src/sky_runtime/live/mod.rs:164 render_page_full (accept head html); runtime-rust/src/sky_runtime/live/mod.rs:777 page handler (call head(model))

#### [P2] Session cookie omits MaxAge → lost on browser restart even with persistent store  ·  status: divergent  ·  effort: S

- **Go behavior:** sessionIDNamed sets the session cookie with MaxAge = sessionTTL (live.go:5638-5662), so with a sqlite/redis/postgres store the session survives a browser restart (cookie persists, checkpoint re-hydrates cold). It also flips SameSite=None; Secure when SKY_LIVE_FRAME_ANCESTORS opts the deploy into iframe embedding.
- **Gap:** Rust page_response (mod.rs:606) emits `{name}={sid}; Path; HttpOnly; SameSite=Lax[; Secure]` with NO Max-Age → a session cookie that the browser drops on close. So even with a persistent store the user loses their session across a browser restart, defeating one of the documented reasons to pick sqlite/redis/postgres. Rust also has no SameSite=None;Secure path, so Sky.Live embedded in a cross-origin iframe (e.g. SkyDeploy console) cannot keep its session.
- **Go loc:** runtime-go/rt/live.go:5638 MaxAge=sessionTTL; runtime-go/rt/live.go:5653 SameSite/Secure (frame-ancestors)
- **Rust loc (fix lands):** runtime-rust/src/sky_runtime/live/mod.rs:606 session_cookie format; runtime-rust/src/sky_runtime/live/mod.rs:648 live_ttl
- **Fill approach:** Append `; Max-Age=<live_ttl().as_secs()>` to the session cookie string in page_response. Add a SKY_LIVE_FRAME_ANCESTORS check that switches SameSite=Lax → SameSite=None plus forces Secure (mirroring csrf::cookies_secure logic). Keep the cookie name/path base-path logic unchanged.

#### [P3] SSE hello payload is `{}` — missing v/sid/ts the client sanity-checks  ·  status: divergent  ·  effort: S

- **Go behavior:** The hello frame data is `{"v":1,"sid":<sid>,"ts":<unixMillis>}` (live.go:5486). v lets future protocol versions tighten the handshake; sid echoes the cookie so the client can sanity-check it landed on the right session; ts gives a server clock reference.
- **Gap:** Rust sends `sse::frame("hello", "{}")` (mod.rs:928) — an empty object. The client's hello listener (client.js:1291) flips connected state on any hello so functionally it reconnects, but it cannot verify the sid matches its cookie (a cross-session mix-up under a misconfigured proxy goes undetected) and any future v-gated protocol step has no version to read. Minor today, but a wire-shape divergence from Go's documented handshake.
- **Go loc:** runtime-go/rt/live.go:5486 helloPayload marshal
- **Rust loc (fix lands):** runtime-rust/src/sky_runtime/live/mod.rs:928 hello frame
- **Fill approach:** Build the hello body as `{"v":1,"sid":<sid>,"ts":<now_millis>}` in sse_handler (sid is the session's sid, already known from the cookie lookup). Use serde_json to serialize. Keeps byte-compat with the client's sid sanity-check.

#### [P3] SSE buffer-drop metric (sky_live_sse_drops_total) + drop-oldest semantics absent  ·  status: divergent  ·  effort: M

- **Go behavior:** Go's per-session SSE outbound channel (SKY_LIVE_SSE_BUFFER, default 16) drops the OLDEST frame when full and increments the sky_live_sse_drops_total{session} metric, so a slow client never blocks the producer and operators can observe drop pressure.
- **Gap:** Rust's sse::channel is a bounded tokio mpsc (capacity from SKY_LIVE_SSE_BUFFER, correct default/clamp) but the producer in drive_session/sse_handler `.await`s on send (sse.rs:24 comment admits this), so a slow SSE consumer applies TCP backpressure that BLOCKS the per-session driver instead of dropping — a wedged browser can stall that session's whole update loop. There is also no drops metric. Divergence in failure-mode (block vs drop) and observability.
- **Go loc:** runtime-go/rt/live.go:6705 drop-oldest; runtime-go/rt/live.go ~SKY_LIVE_SSE_BUFFER + sky_live_sse_drops_total
- **Rust loc (fix lands):** runtime-rust/src/sky_runtime/live/sse.rs:24 (blocking send); runtime-rust/src/sky_runtime/live/mod.rs:487 patch send site
- **Fill approach:** At the patch send site, use try_send; on Full, drop (optionally pop-oldest by draining one then pushing) and increment a sky_live_sse_drops_total counter exported via observability::metrics labelled by session. This keeps the driver non-blocking under a slow client, matching Go's drop-oldest + metric.

#### [P3] Session id is 128-bit (Rust) vs 256-bit (Go); different encoding  ·  status: divergent  ·  effort: S

- **Go behavior:** generateSkySessionID returns 256 bits from crypto/rand, URL-safe base64 (live_store.go:1039).
- **Gap:** Rust new_sid (mod.rs:522) returns 128 bits from OsRng, hex-encoded (32 hex chars). 128 bits from a CSPRNG is cryptographically ample against guessing, so this is not a security defect — but it is a deliberate-looking parity divergence (half the entropy, different alphabet/length). Worth noting because any external system that pattern-matches or length-validates Sky sids (logs, proxies, test fixtures) would see different shapes between backends.
- **Go loc:** runtime-go/rt/live_store.go:1039 generateSkySessionID
- **Rust loc (fix lands):** runtime-rust/src/sky_runtime/live/mod.rs:522 new_sid
- **Fill approach:** Optional: widen new_sid to 32 bytes and URL-safe-base64 encode (base64::URL_SAFE_NO_PAD) to byte-match Go's sid shape. Pure parity polish; current 128-bit hex is already secure.

### http-server-ws-stream (Sky.Http.Server + Server.Stream + WebSocket client/server + Http.Stream + CSRF/middleware)

**How Go works:** Server_listen (rt.go:7628) builds an http.ServeMux, registers each SkyRoute (static dirs via http.FileServer+StripPrefix; method-aware mux pattern when 2+ routes share a path), and wraps every handler in a defer/recover that logs the frame and writes 500. Per request it builds a SkyRequest (headers/cookies/query/form parsed from x-www-form-urlencoded body, body capped via http.MaxBytesReader to 413 on overflow), calls the Sky handler via reflect SkyCall, then drives the returned Task. The response path detects WS-upgrade and stream sentinels (routing to serveWebSocketUpgrade / serveStreamingResponse), applies ContentType (Set, so withHeader can override), copies Headers, applies setSecurityHeaders (nosniff/X-Frame-Options/Referrer-Policy), and for text/html injects per-form CSRF tokens + a dev banner. **How Rust works:** server.rs builds an axum Router, registering each ServerRoute (static via tower_http ServeDir; handlers erased to a non-generic ErasedHandler that maps Err to 500). build_request assembles ServerRequest (RawPathParams for :params, cookies, query, remoteAddr trusting ConnectInfo unless SKY_TRUSTED_PROXY) and extracts a WebSocketUpgrade, body read via to_bytes(max_body()). method_router runs the handler inside WS_UPGRADER/WS_RESPONSE task-locals so a server_web_socket_upgrade returns the real 101; otherwise to_axum_response detects the stream sentinel (serve_streaming_sentinel: bounded-16 mpsc + Body::from_stream), clamps status, sets content-type + copies headers. CatchPanicLayer gives per-handler 500. Middleware (withCors/withLogging/withBasicAuth ct_eq/withRateLimit fixed-window) and RateLimit.allow token-bucket are handler-to-handler wrappers. Server-side and client WebSocket are fully ported (ws_client.rs tokio-tungstenite with SSRF-pinned dial + ping; server WS with origin-glob CSWSH hardening). Http.Stream (http_stream.rs) ports open/forEachChunk/close + the Sub chunks driver with SSRF + a 1024-stream cap. Server.listen binds + axum::serve. There is NO CSRF middleware on the Sky.Http.Server path, NO setSecurityHeaders, NO server-level timeouts, NO graceful shutdown, and NO 413 on oversize body.

#### [P1] Oversize request body silently becomes an empty body instead of a 413  ·  status: divergent  ·  effort: S

#### [P2] Server-side WebSocket has no heartbeat ping (Go pings every 30s)  ·  status: divergent  ·  effort: S

#### [P2] Server-stream withContentType is a hard no-op (Go is best-effort before first emit)  ·  status: stub  ·  effort: M

#### [P3] Server-stream emit lacks a consumer-stall abandon timeout (Go drops + abandons after 30s)  ·  status: divergent  ·  effort: S

- **Go behavior:** The server stream channel is bounded and ServerStream_emit, on a full channel, blocks only up to streamConsumerTimeout (30s) then abandons the stream (deliver() returns false, handle closed). Client disconnect mid-write surfaces as Err (server_stream.go:230-256).
- **Gap:** Rust server_stream_emit does tx.send(chunk).await on a bounded-16 channel (correct backpressure; a dropped receiver returns Err). Go bounds this at 30s. Minor since the bounded channel + backpressure is intentional; only the runaway-stall ceiling differs.
- **Go loc:** runtime-go/rt/server_stream.go:230 ServerStream_emit; runtime-go/rt/server_stream.go:396 deliver consumer-stall timeout
- **Rust loc (fix lands):** runtime-rust/src/sky_runtime/server_stream.rs:125 server_stream_emit
- **Fill approach:** Wrap tx.send(chunk) in tokio::time::timeout(30s, ...); on elapsed, remove the sender from stream_senders (ending the body) and return Err('server.stream emit: consumer stalled'). Keep the existing client-disconnect Err path. Add a STREAM_CONSUMER_TIMEOUT constant mirroring streamConsumerTimeout.


### webview

**How Go works:** `Webview_app(cfg)` (runtime-go/rt/webview.go) is a Task thunk; Task.run forces `webviewAppRun`. It reads init/update/view/subscriptions/window from cfg, derives title (default "Sky.Webview") and size from the `(Int,Int)` tuple (default 1024x720), and creates a `webview_go` window (cgo into WKWebView/WebView2/WebKitGTK). It Binds two JS->Go callbacks: `__skyDispatch(handlerId,args)` resolves the wire payload through a per-render handlers map (renderVNode populates `<sky-id>.<event> -> Msg ctor`) and decodes args via applyMsgArgs into a bounded `msgCh chan any` (cap 32, drops counted); and `__skyLog`. It injects `webviewSharedJS` (Sky.Live's patch-applier subset: focus/cursor/scroll preservation, `__skyReviveScripts`, open-`<select>` defence, full event set). First render: HtmlToVNode + assignSkyIDs + applyStyleInjections -> renderVNode -> SetHtml (or Navigate to a 127.0.0.1 loopback static server when `[live].static` is set, bug #370). Subscriptions run via newSubManager pushing Sub.every ticks into msgCh. A background goroutine drains msgCh, runs update (cliApplyUpdate, which runs returned Cmds via cliRunCmd), re-renders, computes `diffTrees(prev,new)` patches, JSON-marshals them, and `w.Dispatch(w.Eval("__skyApplyPatches(...)"))` on the main thread. `w.Run()` blocks the main OS thread until window close, then tears down subs + loopback. webview_stub.go (`!cgo||!darwin`) returns `Err ErrIo` with a rebuild remediation. sky build flips `CGO_ENABLED=1` on first attempt when `rt.Webview_app` appears in main.go.

**How Rust works:** runtime-rust/src/sky_runtime/webview.rs has two `imp` modules behind `#[cfg(feature="webview")]`. The DEFAULT build (feature off — and the feature is build-blocked on this host per #63 because wry 0.55 / tao 0.35 need webkit2gtk-4.1 + libsoup-3.0 + GTK3 dev libs) compiles the stub: `webview_app` returns `SkyResult::Err` with a `--features webview` remediation, mirroring Go's stub. The real path (feature on) builds a `tao` EventLoop + `wry` WebViewBuilder on the main thread (driven via block_on_current_thread per task.rs), with per-OS build (`build(&win)` off Linux, `build_gtk(vbox)` on Linux). It injects BRIDGE_JS (three delegated listeners: click/input/change only) that posts `{skyId,event,args}` over `window.ipc.postMessage`. It calls init once (warns + drops any non-None Cmd), renders the view via the reused Sky.Live `render_html`+`assign_sky_ids`+`build_index` (HandlerIndex), and seeds `with_html`. The event_loop.run loop parses IPC, resolves the Msg via `HandlerIndex::resolve`, runs update (drops Cmd with a once-warning), re-renders, and does a FULL `window.__skyApply(html)` = `document.body.innerHTML = html` replace via evaluate_script. Window-close exits. Codegen: Project.hs gates `webviewMod`/`webviewUse` + the live submodule on `usesWebview`; ExprEmitter/Emitter route `Webview.app` (a VarTopLevel Ffi.kernel alias) to `webview_app` and force the main-thread Task driver.

**How Go works:** Std.Db in Go (db_auth.go) opens a *sql.DB (sqlite via modernc, postgres via pgx), driver-detected from the URL; placeholder()/placeholders() emit ?/$N per driver. ### runtime-core-task

**How Go works:** Go's Task is an opaque thunk (`func() any` / `SkyTask[E,A]=func() SkyResult[E,A]`); combinators (Task_map/andThen/sequence/parallel/onError/mapError/fromResult/andThenResult) normalise any thunk shape via anyTaskInvoke + reflect fallback, Task_parallel fans out goroutines preserving order with first-err-wins. retryWith (task_retry.go) reads a RetryPolicy record (reflect recordField), drives the thunk maxAttempts times, computeDelay does linear/exponential(2^n, capped 30s)/jitter[0.5,1.5)×math/rand, and callShouldRetry switches on the ShouldRetry ADT (RetryAlways/RetryWhen). **How Rust works:** Rust models Task as a real `Pin<Box<dyn Future<Output=SkyResult<E,A>>+Send>>`; combinators (task.rs) are concrete async fns — map/and_then/on_error/map_error/from_result/and_then_result/sequence/parallel(via tokio::spawn, order-preserving, first-err, JoinError→Err). retry_with is a faithful port: codegen destructures the RetryPolicy/ShouldRetry ADT at the call site into primitive args (max_attempts/base_ms/jitter/kind + a should_retry closure) so the runtime needs no reflection; retry_compute_delay mirrors Go (saturating arithmetic, LCG jitter). ### kernels-stdlib (Cache, Config, Csv, Compression, Email, Crypto/AEAD/Bytes, Time/Std.Time, Random, env-prefix, dotenv, doc-catalog, validate, Math, String, Money/Decimal)

**How Go works:** Go implements each stdlib module as a `rt` package file exposing `Module_fn(args ...any) any` kernels (or `RegisterPure` entries for Std.Time). Values are `any`-typed and shape-coerced via reflect helpers (`recordField`, `AsList`, `AsInt`, `SkyADT`). Cache uses hashicorp/golang-lru with lazy TTL on get and eviction counters carefully reversed for manual remove/purge. Config parses TOML/YAML/JSON into a `map[string]any` tree, runs a `func(any)any` decoder; `config_int` accepts whole-number floats, `config_nullable` swallows inner decode failures to Nothing. Csv uses encoding/csv (RFC4180, default `\r\n` writer terminator). Email does real REST for Resend/SendGrid/SES-SigV4 + net/smtp, with `SKY_EMAIL_DRY_RUN`/`SKY_EMAIL_ENDPOINT_*` overrides. Crypto AEAD reads a RAW 32-byte key string; aesKeyFromPassword returns raw PBKDF2 bytes (100k iters). Std.Time uses embedded tzdata, clamps addMonths/addYears to month-end, and computes period boundaries via Go time.Date in the loaded zone (endOfDay = next-day-midnight − 1ms, DST-correct). Random_float takes (lo,hi) and returns lo+r*(hi-lo). dotenv.go runs an `init()` that auto-loads `.env` before main with shell>‌.env precedence and a careful inline-comment/quote-stripping parser. env_prefix.go namespaces every internal SKY_* read through `skyEnvName`, switchable via `[env] prefix`.

**How Rust works:** Rust implements each module as a typed `sky_runtime/<mod>.rs` with monomorphic generic kernels returning `SkyResult`/`SkyTask`; codegen routes Ffi.kernel names through `Kernel.hs` (mostly `toSnakeCase`, with explicit overrides) and emits some hardcoded FFI wrappers in `Emitter.hs`. Cache is a handle registry with a value-erased `Box<dyn Any>` linear-scan store (correct-by-construction downcast); maxBytes is NOT enforced (warn-once). Config reuses the JSON `Decoder<E,T>` over serde_json::Value: TOML/YAML parse into the same Value then the shared json `decode_*` kernels run; `config_nullable` propagates the inner Err (does not swallow to Nothing); `json_decode_int` uses serde `as_i64()` (rejects `3.0`). Csv uses the `csv` crate (test shows LF output). Email mirrors Go plus real SMTP via lettre and SSRF guards. Crypto AEAD base64-ENCODES the 32-byte key (aesKeyFromPassword returns base64) and base64-decodes on use. Time is chrono/chrono-tz; addMonths clamps to month end, but endOfDay = startOfDay + 86_400_000 − 1 (not DST-correct) and time_format does naive sequential `.replace()` of a partial Go-layout token set. Random_float is hardcoded in Emitter.hs as `random_float(_: ())` returning [0,1), ignoring lo/hi. There is NO `.env` auto-load at startup (only explicit `System.loadEnv`, with a naive parser) and NO `[env] prefix` indirection — `live/mod.rs` reads `SKY_LIVE_PORT` etc. directly. doc_catalog has no Rust port (compiler-internal sky-doc TUI only).

### tui

**How Go works:** Go has two entry points: `Tui_program` (view→String, raw frame) and `Tui_app` (view→Element, Std.Ui→cells). `tuiAppRun` reads cfg fields init/update/view/subscriptions plus OPTIONAL onKey and guard; reads CanvasWidth/CanvasHeight (default 1280×720, capped at 100k with a tuiWarn). It refuses non-TTY stdin AND TERM=dumb OR empty TERM, honours NO_COLOR, enters raw mode storing oldState, publishes a `tuiState` to a global so `safeGo` panic-recover and a signal handler (installCleanShutdown traps SIGTERM/SIGHUP/SIGQUIT/SIGINT → tuiTeardown → exit 128+signum) can restore from any goroutine. It enables SGR mouse (?1000;1006h) and bracketed paste (?2004h). A key-reader goroutine decodes bytes (tuiDecodeKey: chars, named keys, Ctrl-letters, CSI arrows w/ modifier bits, mouse, paste-start/end, fn-keys), aggregates bracketed paste into ONE event capped at 1 MiB of runes, and a SIGWINCH watcher pushes a tuiResizeMsg into the same channel so resize reflows even with no keystroke. The main loop intercepts Tab/Shift-Tab/arrows for focus nav, mouse for hit-test+wheel-scroll, Enter/Space to activate, edits focused inputs, batches up to 64 queued msgs before one repaint, runs `guard` before each update (Err → stamp Notification field), wraps update in a Msg span, and paints via paintDiff against the prev grid (only changed cells). Ctrl-C with NO onKey hard-exits. tuiTeardown does an ordered mouse-off→SGR-reset→show-cursor→alt-screen-exit→DECSTR/charset/keypad resets→Restore→final flush (debugged for mosh). Unsupported Std.Ui attrs route to a deduped tuiWarn sink flushed at exit unless SKY_TUI_QUIET (SKY_TUI_LOG writes a ledger). tuiMaxContentH=50000 caps grid allocation, tuiSoftWarnH=10000 warns. sanitiseRune maps controls to · / ␤(newline)/space(tab,CR), keeping rune count. **How Rust works:** Rust has `tui_app` (String view) and `tui_app_ui` (Element view) sharing the same generic shape but NOT a shared loop for the Element path. `tui_app_ui` requires init/update/view/subscriptions AND on_key (FOnKey is a non-optional generic param; codegen always emits the field) — there is NO `guard` parameter, so the cfg's guard field is silently dropped. It refuses TERM=dumb only (not empty TERM, not non-TTY). A `TuiGuard` RAII enters crossterm raw mode + alt-screen + hide-cursor + mouse (?1000;1006h for the UI driver) and registers a System.exit hook; teardown (mouse-off→show-cursor→alt-screen-off→disable_raw_mode) runs once via an AtomicBool from Drop OR the exit hook. The async loop handles mouse wheel/click, Tab/Shift-Tab/arrow focus nav, checkbox/radio toggle, textarea-Enter→newline, input editing (focus.rs edit_input), Enter/Space activation, else on_key. render_with_focus (layout.rs) walks the typed Element/attrs to a Block of styled runs, resolves the logical-pixel canvas (1280×720 HARDCODED — no cfg override), emits SGR (bold/italic/underline/overline/strike/reverse + 38;2/48;2 truecolour, NO_COLOR honoured), and `paint()` issues ESC[2J+home then the FULL frame every tick. cell.rs sanitize_rune maps C0+DEL+C1 controls to a plain space (no ␤ cue). diff.rs exists and is unit-tested but is UNUSED by the app loop. No SIGWINCH watcher, no bracketed-paste aggregation, no warn sink, no content-height cap, no general signal trap, no Ctrl-C hard-exit fallback.

### codegen-parity (Go vs Rust emitter)

**How Go works:** The Go backend lowers canonical Sky (src/Sky/Build/Compile.hs, ~16k lines) into a typed Go IR (Generate/Go/{Ir,Builder,Type,Record,Kernel}.hs). Type-directed lowering threads solver RegionTypes + LowerCtx so every slot lowers with its concrete Go shape; Type.typeToGo maps every Sky type to a Go type and NEVER falls through to a wrong concrete type — bad arity / extensible records degrade to `any`/`[any]`. Parametric record aliases emit Go generics (`Cfg_R[T1 any]`) with subset-record `_skysynth` TVar synthesis (Record.hs). Tail-recursion is detected by TailCallOpt.isTailRecursive and emitted as `[GoForever <stmts>]` so foldl/find/any/drop run in constant stack (Compile.hs:3422,4580). Cons-chain matches get explicit per-arm length guards (consChainLength + collectSpineHeads, Compile.hs:12353) because Go `switch` has no slice patterns. Reserved Go identifiers are rewritten with a trailing `_` (reservedGoNames, Compile.hs:4684). Reachable-from-Sky panics route through rt.IntDiv/Rem/AsInt/Coerce and `func main()` opens with `defer rt.LogPanicAndExit()` which recover()s, classifies (DivisionByZero/IndexOutOfRange/…), logs a structured errId line, and exits 1. FFI is auto-generated by FfiGen.hs (1875 lines).

**How Rust works:** The Rust backend (src/Sky/Generate/Rust/*) walks the same canonical AST. ExprEmitter.exprToRustInner handles all 24 Expr_ constructors; TypeRenderer.typeToRustString maps Sky types to Rust types and parametric record aliases emit generic structs (TypeEmitter.aliasToRustTypeDef RStructDef with `gens`), with guardBareAny as the wildcard-any soundness gate. The multibackend entry (Emitter.entryPointSection) computes mainIsTask and block_on's a Task-returning sky_main, dropping Task.run for backend-app drivers (matches Go's entry semantics). Cons-chain matches lower to Rust slice patterns `[x, y, rest @ ..]` (patternToMatchString), which enforce minimum-length natively, so the Go length-guard machinery is unneeded. Reserved Rust keywords are raw-escaped (Naming.rustSafeIdent) and user modules colliding with kernel prefixes get `user_` disambiguation. The HTTP server has a CatchPanicLayer (per-request recovery). FFI is auto-generated by Build/Rust/Ffi.hs (784 lines). Crucially absent: any tail-call-to-loop transform, an entry-level panic classifier, and typeToRustString falls through to a literal "String" for unhandled shapes; a second shadow emitter (substVar) re-implements binop/case/list with weaker coverage.

#### [P1] No TCO: tail-recursive Sky functions recurse on the Rust call stack (foldl/find/any/all/member/drop overflow)  ·  status: missing  ·  effort: L

- **Go behavior:** Go detects tail-position self-calls via TailCallOpt.isTailRecursive and emits the body as `[GoForever <stmts>]` where each tail call becomes param-reassignment + `continue`, giving constant stack. foldl/find/any/all/member/drop and every user tail-recursive function run in O(1) stack even at millions of elements.
- **Gap:** The Rust backend has ZERO tail-call optimisation — defToRustItem emits the body straight through exprToRustString with no loop transform. Every recursive Sky function (including the stdlib's auto-TCO'd foldl/find/any/all/member/drop, which Sky's own docs promise are constant-stack) recurses on the native Rust call stack and overflows on large inputs. A Sky.Cli batch job folding a 200k-element list — fine on Go — aborts with a stack overflow on Rust. This silently breaks the documented stack-safety contract for a whole tier of stdlib functions.
- **Go loc:** src/Sky/Build/TailCallOpt.hs:isTailRecursive; src/Sky/Build/Compile.hs:3422; src/Sky/Build/Compile.hs:4580
- **Rust loc (fix lands):** src/Sky/Generate/Rust/Builder/ModuleEmitter.hs:defToRustItem (335,602); src/Sky/Generate/Rust/Builder/ModuleEmitter.hs (new tailExpr-based loop emitter)
- **Fill approach:** Port TailCallOpt.isTailRecursive to drive a Rust `loop { ... }` emission in defToRustItem: detect tail-position self-calls in the Let/Case/If tails, wrap the body in `loop {`, rewrite each tail self-call to reassign the params (`a = <new>; b = <new>; continue;`) and every other tail to `return <expr>;`. Mirror Go's func-typed-param skip. Lands in ModuleEmitter.hs; reuse the existing tailExpr walker for tail detection.

#### [P1] No synchronous-panic gate on fn main(): div-by-zero / index-OOB / unreachable abort with a raw Rust backtrace instead of a classified Sky Error  ·  status: missing  ·  effort: M

- **Go behavior:** Every emitted `func main()` opens with `defer rt.LogPanicAndExit()`. On any synchronous panic reachable from Sky (DivisionByZero, IndexOutOfRange, CoerceFailure, TypeMismatch, NilDereference, CompilerBug, Unexpected) it recover()s, classifies the panic, emits a structured Error log line with a 4-byte errId (JSON-aware via SKY_LOG_FORMAT), and exits 1 — never dumps a Go stack. This is the v0.15.43 synchronous-panic gate covering Sky.Cli/Sky.Tui/batch shapes.
- **Gap:** The Rust `fn main()` has no `std::panic::catch_unwind` + classifier. A synchronous panic in a non-server app (integer divide-by-zero from the raw `/` emit, an arithmetic overflow, an index-out-of-range, or the `unreachable!()` from a refutable arg pattern) aborts the process with a raw Rust panic message and exit code 101, not Sky's classified structured-error + exit 1. The HTTP CatchPanicLayer covers only per-request server handlers; Sky.Cli / Sky.Tui / cron jobs are unprotected. Operators lose the errId-correlated structured log Go guarantees.
- **Go loc:** src/Sky/Build/Compile.hs (func main defer rt.LogPanicAndExit); runtime-go/rt/rt.go:LogPanicAndExit

- **Fill approach:** Add a runtime `log_panic_and_exit(payload)` to core.rs that classifies the panic payload string (divide by zero / index out of bounds / unreachable / overflow → Sky panic kinds), emits the structured errId log line (honouring SKY_LOG_FORMAT), and `process::exit(1)`. In entryPointSection wrap the sky_main() call in `std::panic::catch_unwind(...)` (or install a panic hook before block_on) for both the Task and non-Task entry branches.

## Cross-cutting critic

The ten domain auditors each owned one subsystem, so three classes of parity risk fell through the cracks: (1) mechanisms that are SHARED infrastructure consumed by every domain (the production gate, the env-var read surface, panic classification, the federation wire format), where no auditor owns "the mechanism itself"; (2) whole Go subsystems that map to NO domain (the OTel/OTLP push-trace exporter `telemetry/otel.go`, the `[env] prefix` multi-tenant namespace rewrite `skyGetenv`); (3) default-posture security questions that sit between "who serves the endpoint" (one auditor) and "who authenticates it" (another), where each assumed the other covered it (federation ingest token default-open in Rust).

PRODUCTION GATE — split-brain. Rust has TWO implementations of the ENV/SKY_ENV gate: the canonical `telemetry::production_from_env` (telemetry.rs:138, lowercases correctly) AND an inline duplicate `ws_production` (server.rs:583) used ONLY by the WebSocket origin gate that does NOT lowercase. So `ENV=Development` or `ENV=Dev` is dev everywhere (console hidden, banner shown, metrics open) but PRODUCTION for the WS-origin CSWSH gate — the one surface where mis-classifying as production flips the empty-originPatterns 403. The console_proxy, csrf cookie-secure, and server cookie-secure all correctly route through the canonical fn; the WS path is the lone divergent copy. No single domain auditor compared the gate's call sites across console+banner+metrics+ws because each only read its own subsystem's use of it.

ENV-VAR READ SURFACE — systematic. A diff of actually-read env vars (env::var vs os.Getenv, not mere mentions) shows 30 vars Go reads that Rust never reads. The load-bearing ones beyond already-filed domain gaps: the entire `OTEL_EXPORTER_OTLP_{ENDPOINT,HEADERS,PROTOCOL}` + `OTEL_SERVICE_{NAME,VERSION}` + `OTEL_TRACES_SAMPLER_ARG` group (Rust has zero OpenTelemetry trace export — the documented Honeycomb/Tempo/Datadog push path is Go-only); `SKY_DEV_BANNER` (Rust banner honours SKY_CONSOLE_EMBED + SKY_CONSOLE_AUTH=off but NOT the dedicated SKY_DEV_BANNER=off/0 kill-switch); `SKY_OBSERVABILITY_BUFFER` / `SKY_OBSERVABILITY_PUSH_INTERVAL_MS` (federation tuning inert); `SKY_LIVE_NAMESPACE` / `SKY_SERVICE_NAME` (federation/metric service-identity labels). The `[env] prefix` multi-tenant rewrite (Go's `skyGetenv` translates the whole internal SKY_* namespace to MYAPP_*) has NO Rust equivalent — Rust reads raw SKY_* names, so a Sky app with `[env] prefix = "MYAPP"` silently loses every internal-var override on Rust.

PANIC CLASSIFICATION — end-to-end gap across ALL synchronous app shapes. Go injects `defer rt.LogPanicAndExit()` as the first statement of every emitted main() (Compile.hs:12873); any escaping panic is recovered, classified (DivisionByZero/TypeMismatch/IndexOutOfRange/NilDereference/CompilerBug/Unexpected), and emitted as ONE structured Error log line with a 4-byte errId honouring SKY_LOG_FORMAT=json, then exit 1. Rust's generated main() (Emitter.hs:402) has NO `panic::set_hook` and NO `catch_unwind` anywhere in the runtime or codegen (grep-confirmed zero hits) — an escaping panic dumps a raw Rust backtrace and aborts, the exact unclassified-stack-dump behaviour Go's v0.15.43 gate eliminated. The Rust no-panic-from-well-typed-Sky thesis reduces the FREQUENCY but does not CLOSE the surface: a poisoned-lock `into_inner` re-panic, an arithmetic-overflow site the audit missed, or any 3rd-party FFI crate panic still escapes unclassified. Worse, even the clean Err-return path diverges: `SkyResult::Err(e) => eprintln!("{:?}", e)` is a Debug-format dump with no errId, no classification, no JSON — vs Go's structured two-level error. No domain auditor owned "what happens when a panic/Err escapes main across cli+tui+webview+server" because that is the codegen-entry seam, not any runtime subsystem.

FEDERATION DEFAULT-POSTURE — security, falls between sender and receiver auditors. Go auto-generates a 32-byte random ingest token at boot (IngestTokenInit) and passes it to spawned children, so `/_sky/observability/ingest` is CLOSED by default. Rust's `ingest_token_blocked` (console.rs:225) returns None (open) when `SKY_INGEST_TOKEN` is unset — and nothing auto-generates it. So a Rust app that doesn't manually set the env var accepts unauthenticated forged telemetry POSTs from anyone on the network. Separately, the federation WIRE FORMAT diverges: Go's receiver REQUIRES a `namespace` field (400 "missing namespace" without it) and labels everything subapp=<namespace>; Rust's push_exporter builds `{"logs":[],"spans":[]}` with NO namespace and NO metrics array — so Rust→Go federation is 400-rejected and Rust↔Rust federation loses sub-app labelling. console-observability owned the console-read side, http-server owned request auth; neither owned the federation endpoint's default-closed posture or the push/ingest payload contract.

OTHER CROSS-CUTTERS. `Std.Ui.Lazy` (LRU subtree cache + SKY_UI_LAZY_CAP) is entirely absent in Rust — a documented Std.Ui primitive with no codegen mapping (only Task.lazy maps); spans the live-diff renderer and ui domains, owned by neither. XFF-trust asymmetry: Go trusts X-Forwarded-For/X-Real-IP UNCONDITIONALLY for rate-limit keying + access logs (an IP-spoof rate-limit-bypass on Go's side), while Rust gates it behind SKY_TRUSTED_PROXY (default off) — so a Rust app behind a proxy without that var rate-limits all clients into one proxy-IP bucket; a real behavioural divergence in opposite directions on the same security surface. Admin-token alias coverage differs (Go honours SKY_METRICS_TOKEN + SKY_CONSOLE_TOKEN_SECRET; Rust honours SKY_ADMIN_TOKEN/SKY_CONSOLE_TOKEN/SKY_METRICS_TOKEN but not SKY_CONSOLE_TOKEN_SECRET).

### Cross-cutting gaps (missed by per-domain partition)

#### [P1] Generated Rust main() has no panic classifier — escaping panic dumps a raw backtrace + aborts (no LogPanicAndExit parity) across cli/tui/webview/batch  ·  area: codegen-entry (all synchronous app shapes) + logging + panic-recovery  ·  effort: M

- **Why missed:** This lives at the codegen main()-emission seam, not in any runtime subsystem. Each domain auditor read its own runtime module's panic handling (db-auth hunted panic vectors, tui owned teardown, server owned per-request recover) but none owned 'what the emitted main() does when a panic or Err escapes the whole program' — which is the same code for every app shape and belongs to no domain.
- **Go behavior:** Codegen injects `defer rt.LogPanicAndExit()` as the FIRST statement of every emitted func main() (Compile.hs:12873).
