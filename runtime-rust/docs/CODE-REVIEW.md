# Sky Rust backend — code-review checklist

A file-by-file checklist for a **line-per-line** review of the Rust backend against
six criteria, in priority order: **security > correctness > soundness > efficiency
> completeness > readability** (plus consistency + coherence with the rest of the
codebase). One pass, one file at a time.

**How to use this document.**
- Review files **top to bottom within each component** — they are ordered
  **leaf-first** (foundational / depended-upon files first; aggregators like
  `mod.rs` / facades last), so you build understanding bottom-up.
- Columns:
  - **Human review** / **Agent review** — `☐` until reviewed, then `☑` (mark who reviewed it).
  - **File** — repo-relative path.
  - **Notes** — one-line purpose (what the file does). *Pre-filled.*
  - **Risk** — what to scrutinise here (the likely failure modes). *Pre-filled hint; refine during review.*
  - **Problems** — findings from the sweep. *Filled during review.*
  - **Suggested fixes/changes** — proposed remedy per finding. *Filled during review.*

> Generated by an automated skim (purpose + risk only). The **Problems** and
> **Suggested fixes/changes** columns are intentionally empty — they are filled
> during the actual review sweep.
