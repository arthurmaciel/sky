# Sky Rust backend — code-review checklist

A file-by-file checklist for a **line-per-line** review of the Rust backend against
six criteria, in priority order: **security > correctness > soundness > efficiency
> completeness > readability** (plus consistency + coherence with the rest of the
codebase). One pass, one file at a time.

**How to use this document.**
- Files are grouped by component and ordered **leaf-first** (foundational /
  depended-upon files first; aggregators / `mod.rs` / facades last).
- Columns: **File** · **Purpose** (one line) · **Risk** (what to scrutinise) ·
  **Last audited** (`YYYY-MM-DD`; empty = never audited — a non-empty date is the
  "audited" mark) · **Findings** (concrete issues, bulleted; `—` = clean) ·
  **Suggested fix** (per finding) · **Fix** (✅ fixed + built · ⏸️ deferred (+reason) ·
  ➖ no-defect · ❌ attempted, won't verify — each with a date).
- A **living ledger**: each re-audit stamps **Last audited** and only re-sweeps
  files changed since their last date. Skill: `sky-rust-backend:principles-audit`.
- **Latest full re-audit: 2026-06-27** (whole codebase, swarm; see section below). Prior full: 2026-06-19 (whole codebase, 131 code/script/skill files) —
  see the dated section immediately below for severity summary + high/medium dispositions.
