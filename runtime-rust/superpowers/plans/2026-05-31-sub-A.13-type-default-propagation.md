# Sub-A.13 — Type-default propagation for empty literals (Rust codegen)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the four cargo errors blocking `examples/00-standard-libs` from compiling on `target=rust`, so the headline parity gate ("120/120 assertions pass on target=rust") holds.

**Architecture:** Sky's HM solver already infers concrete types at every region — they sit in `Solve.SolvedTypes._stRegions`. The Rust codegen discards the region annotation at `exprToRustString ctx (Ann.At _ expr) = exprToRustInner ctx expr` and so emits bare `vec![]` / `SkyMaybe::Nothing` / `SkyResult::Err(...)` even when the type is known. The fix plumbs `_stRegions` through `EmitCtx` and looks it up at the top of `exprToRustString`, injecting `ecExpectedType :: Maybe T.Type` so the three empty-literal emit sites can emit turbofish (`Vec::<i64>::new()` etc.) instead. When the lookup fails or the type still carries unbound variables, default to `i64` and surface a dedup'd stderr warning so user-code regressions are visible.

**Tech Stack:** Haskell (GHC 9.4.8) compiler in `src/Sky/Generate/Rust/`, `cargo` for the downstream Rust build.

**Scope guard:** Rust-target-only. No changes to `src/Sky/Generate/Go/`, `runtime-go/`, the FfiGen byte-identity surface, or any Sky stdlib source. Every Haskell touch site is reachable only through `Sky.Generate.Rust.*`. The cross-backend rule ("never break Go") is verified at Task 11 via the `FfiGen`/`Toml`/`Kernel` byte-identity specs.

- [ ] **Step 1: Add a dedup'd warning helper**

Add to `src/Sky/Generate/Rust/Builder.hs` (or a sibling module if Builder is already large):

```haskell
-- Sub-A.13: dedup'd warning emitted once per (file, kind) when codegen falls
-- back to a default type for an empty literal. Reusing the unsafePerformIO
-- IORef idiom already present in this file for analyzer state (see
-- builderFfiOpaques uses elsewhere).
{-# NOINLINE typeDefaultWarnings #-}
typeDefaultWarnings :: IORef (Set.Set String)
typeDefaultWarnings = unsafePerformIO (newIORef Set.empty)

emitTypeDefaultWarning :: String -> a -> a
emitTypeDefaultWarning key result = unsafePerformIO $ do
    seen <- readIORef typeDefaultWarnings
    when (not (Set.member key seen)) $ do
        modifyIORef' typeDefaultWarnings (Set.insert key)
        hPutStrLn stderr $ "warning: Rust codegen defaulted unconstrained type at "
            ++ key ++ " — value should be discarded; if it is used as i64 by "
            ++ "accident, annotate the source"
    return result
```

| Risk | Mitigation |
|---|---|
| The i64 default silently changes behaviour in user code | Stderr warning at every fallback (Task 8). Dedup'd so it doesn't spam, but visible on first encounter. |
| `Sky.Type.Type` module-name guess wrong | Task 2 step 2 explicitly checks via grep before relying on the import. |

| Closure-param inference (error 3) doesn't fall out from fixing Nothing | Task 6 step 3 notes that error 3 may need separate handling. If so, document the residual limitation in the commit message and the README "Known limitations" table — do not balloon the plan. |

If any task's "Verify it passes" step fails AND the cause isn't immediately obvious, STOP and either (a) revert that task's commits to a known-good state, or (b) escalate to the user with the exact failure output rather than guessing.
