# Sub-D — Sync v0.15.40..v0.15.44 + Rust adaptations (no `any` in Rust target)

**Date:** 2026-05-31
**Status:** Approved — ready for plan
**Scope:** Land upstream `anzellai/sky` through `v0.15.44` (ccd0b2ff) into `feat/runtime-rust`. Ship the Rust-side adaptations that the new upstream surfaces require, **without ever lowering Sky's `any` to `Box<dyn Any>` / `Arc<dyn Any>` on the Rust target**. The point of the Rust backend is to use Rust's static type system; runtime type erasure defeats that.
**Branch:** `feat/runtime-rust` (work on a sister branch `feat/runtime-rust-subd-v0.15.44`, PR back to `feat/runtime-rust` — never to `upstream/main`).
**Builds on:** sub-A (stdlib parity), sub-B (Std.Db), sub-C (Std.Auth), the sub-A.13 plan (orthogonal — empty-literal type defaulting; can land independently).

---

## 1. Context

`/sync-upstream` against `upstream/main` (v0.15.44 tip `ccd0b2ff`) was attempted on 2026-05-31. The thin-seam merge resolved the two expected conflicts (`app/Main.hs` + `src/Sky/Build/Compile.hs`) cleanly, the compiler built, and Go FFI byte-identity held. But the Rust sweep failed at `examples/rust/17-db-todo-cli` and `examples/rust/18-auth-signup` with 3 cargo errors each. The merge was aborted per the skill's "do NOT commit a broken merge" rule; the branch is parked at `28d76ec5` (the blocker-doc commit).

Root cause: upstream `v0.15.44` part 3 (`5947cf81 feat(task): Task.retryWith + RetryPolicy combinators`) added a record alias with an `any`-typed field:

```elm
type alias RetryPolicy =
    { maxAttempts : Int, baseMs : Int, kind : Int, jitter : Bool
    , shouldRetry : any
    }
retryAlways : any
retryAlways = Ffi.kernel "Task_retryAlways"
retryOn predicate policy =
    { policy | shouldRetry = predicate }
```

The Go target's lowering of `any` is `interface{}` — runtime dynamic dispatch eats both the sentinel from `linearBackoff` and the closure from `retryOn`. The Rust target's lowering of `any` is currently `String`, which can't hold either value at runtime; the build fails.

**The naive fix** — widen Rust's `any` to `Arc<dyn Any + Send + Sync>` — was considered and rejected. That path:

- adds runtime downcasts at every `shouldRetry` call,
- makes the field type-erased (`cargo build` no longer enforces the predicate's shape statically),
- imports Go's `interface{}` semantics wholesale, defeating the reason to have a Rust backend at all,
- and accepts every future upstream `any`-field surface as more `Arc<dyn Any>` debt.

**The right fix:**

1. **Codegen refuses `any` in record fields** on `target=rust` — clean compile-time error with a pointer to the override + upstream issue.
2. **Local stdlib override** ships an HM-pure ADT shape for `Sky.Core.Task` that the Rust target loads in place of the upstream version while upstream is being asked to redesign.
3. **Upstream redesign filed** as an `anzellai/sky` issue/PR proposing `type ShouldRetry e = RetryAlways | RetryWhen (e -> Bool)` so the override eventually deletes.

Two other v0.15.44 surfaces also need Rust work, both straightforward:

- **AES-GCM + ChaCha20-Poly1305 + Sky.Core.Bytes** (`1ba83cc2`) — new crypto kernels (8 of them) + a `type alias Bytes = String` module that needs zero codegen change.
- **HttpResponse + Sky.Http.Server HM sigs** (`6a17bbd2`) — zero impact on Rust target verified by grep (no `examples/rust/*` imports `Sky.Core.Http` or `Sky.Http.Server`).

After sub-D, `feat/runtime-rust` is synced with `upstream/main` at `ccd0b2ff`, 18/18 Rust examples build clean, and the Rust target's type-system invariant ("every field has a statically-known concrete Rust type, no runtime erasure") is preserved.

## 3. Design

### 3.1 Codegen rejection of `any` in record-field positions

**Where:** new pass in `src/Sky/Generate/Rust/Project.hs` runs immediately after type solving, before `buildProgram`. Walks every record alias in the union of `(canMod : map snd validDeps)`. For each field, resolves the field type via the solver's region map. If the resolved type is `T.TVar "any"` or contains `T.TVar "any"` at any depth, emits a structured diagnostic and returns `Left "any-typed record field rejected on target=rust"`.

**Diagnostic shape:**

```
error[Rust]: any-typed record field on `--target rust`
  --> <file>:<line>:<col>
   |
138|     , shouldRetry : any
   |                     ^^^ Rust target requires statically-typeable fields
   |
   = note: the Go target lowers `any` to interface{} (runtime dynamic dispatch),
           which defeats Rust's static type system. The Sky stdlib should encode
           heterogeneous fields as an ADT — e.g.
           `type ShouldRetry e = Always | Custom (e -> Bool)`.
   = note: stdlib modules with known `any` fields ship a Rust-only override at
           `runtime-rust/sky-stdlib-overrides/<Module>.sky` that the Rust
           target loads in place of upstream.
   = note: tracked upstream: <link to issue once filed>
```

**Why this position:** before `buildProgram` means before any IR is emitted, before any cargo work runs, before the user has waited 30 s for `cargo build` to fail with E0308. Fast, clean, actionable.

### 3.2 Stdlib-override loader

**Where:** `src/Sky/Build/Compile.hs`, the existing path that resolves stdlib module sources.

**Mechanism:**

```haskell
-- Before resolving any stdlib path, check for a target-specific override.
-- TargetRust looks under runtime-rust/sky-stdlib-overrides/ first; falls
-- through to upstream sky-stdlib/ when no override exists. TargetGo is
-- never affected — it always reads sky-stdlib/ directly.
resolveStdlibPath :: Toml.Target -> ModuleName -> IO (Maybe FilePath)
resolveStdlibPath TargetRust modName = do
    let overridePath = "runtime-rust" </> "sky-stdlib-overrides"
                       </> moduleNameToPath modName <.> "sky"
        upstreamPath = "sky-stdlib" </> moduleNameToPath modName <.> "sky"
    overrideExists <- doesFileExist overridePath
    if overrideExists
        then return (Just overridePath)
        else do
            upstreamExists <- doesFileExist upstreamPath
            return (if upstreamExists then Just upstreamPath else Nothing)
resolveStdlibPath TargetGo modName = do
    let upstreamPath = "sky-stdlib" </> moduleNameToPath modName <.> "sky"
    upstreamExists <- doesFileExist upstreamPath
    return (if upstreamExists then Just upstreamPath else Nothing)
```

**Why this design:**

- **Go path completely unchanged** — the function pattern-matches on the target; Go-side reads only `sky-stdlib/`.
- **Rust override is opt-in per module** — only modules with a file at `runtime-rust/sky-stdlib-overrides/<Module>.sky` get overridden; everything else reads upstream.
- **The override is git-tracked** — it's a normal Sky file in the repo, reviewable, diff-able, deletable when no longer needed.
- **Embedded runtime resolution** still picks up overrides via the `EmbeddedRuntime.hs` TH glob — extending the glob is one line.

**Edge case:** if the embedded runtime stdlib (compiled into the `sky` binary via TH) is used instead of the on-disk one, the override needs to ship via the same TH path. `src/Sky/Build/EmbeddedRuntime.hs` already lists module file paths; add `runtime-rust/sky-stdlib-overrides/` as a second search root with priority over `sky-stdlib/` on `TargetRust`.

### 3.3 ADT-shaped local override for Sky.Core.Task

**File:** `runtime-rust/sky-stdlib-overrides/Sky/Core/Task.sky`

**Shape:** identical surface to upstream Sky.Core.Task except the retry section:

```elm
-- ─── Retry combinators (Rust override — ADT shape) ──────────────────

-- | Predicate ADT for `RetryPolicy.shouldRetry`. Upstream uses
-- `shouldRetry : any` which relies on Go's `interface{}` runtime;
-- Rust target requires this to be statically typed. Each constructor
-- corresponds to one of the value shapes upstream supports.
type ShouldRetry e
    = RetryAlways
    | RetryWhen (e -> Bool)


type alias RetryPolicy e =
    { maxAttempts : Int
    , baseMs : Int
    , kind : Int
    , jitter : Bool
    , shouldRetry : ShouldRetry e
    }


-- | Default predicate — retry every error. Replaces upstream's
-- `retryAlways : any` sentinel; semantically identical, statically
-- typed.
retryAlways : ShouldRetry e
retryAlways = RetryAlways


linearBackoff : Int -> Int -> RetryPolicy e
linearBackoff maxAttempts delayMs =
    { maxAttempts = maxAttempts
    , baseMs = delayMs
    , kind = 0
    , jitter = False
    , shouldRetry = retryAlways
    }


exponentialBackoff : Int -> Int -> RetryPolicy e
exponentialBackoff maxAttempts baseMs =
    { maxAttempts = maxAttempts
    , baseMs = baseMs
    , kind = 1
    , jitter = False
    , shouldRetry = retryAlways
    }


withJitter : RetryPolicy e -> RetryPolicy e
withJitter policy = { policy | jitter = True }


retryOn : (e -> Bool) -> RetryPolicy e -> RetryPolicy e
retryOn predicate policy = { policy | shouldRetry = RetryWhen predicate }


retryWith : RetryPolicy e -> Task e a -> Task e a
retryWith = Ffi.kernel "Task_retryWith"
```

**Type-system observations:**

- `ShouldRetry e` is parametric in the error type — same as how upstream's `any` was meant to behave per occurrence. Sky's HM solver instantiates `e` per call site naturally.
- `RetryPolicy e` becomes parametric; the existing v0.15 Go-generics-on-record-aliases work already supports this on both targets (`type Cfg msg = { onSubmit : msg ... }` → `Cfg_R[T1 any]` in Go, `Cfg_R<T1>` in Rust).
- The Go target also benefits if this ADT shape is adopted upstream — `task_retry_with` already does a type assertion on `shouldRetry`; matching on the ADT is one cheaper switch instead of a reflect call.

### 3.4 Rust runtime: `task_retry_always` + `task_retry_with`

**File:** `runtime-rust/src/sky_runtime/task.rs` (additions, ~150 LOC)

**Shape:**

```rust
/// ADT mirror of Sky's `ShouldRetry e`. Tag enum, no boxing.
#[derive(Clone)]
pub enum ShouldRetry<E> {
    Always,
    When(Arc<dyn Fn(E) -> bool + Send + Sync>),
}

/// Mirror of Sky's RetryPolicy ADT. Generic over the error type so the
/// `RetryWhen` arm carries a typed predicate. No Any, no downcasts.
pub struct RetryPolicy<E> {
    pub max_attempts: i64,
    pub base_ms: i64,
    pub kind: i64,
    pub jitter: bool,
    pub should_retry: ShouldRetry<E>,
}

/// Sky `retryAlways : ShouldRetry e` — zero-arg ctor of the Always variant.
pub fn task_retry_always<E>() -> ShouldRetry<E> {
    ShouldRetry::Always
}

/// Sky `retryWith : RetryPolicy e -> Task e a -> Task e a` — run the
/// task, retry on Err up to maxAttempts times with policy-specified
/// backoff between attempts. Returns the first Ok or the last Err.
pub fn task_retry_with<E, A>(
    policy: RetryPolicy<E>,
    task: SkyTask<E, A>,
) -> SkyTask<E, A>
where
    E: Send + Clone + 'static,
    A: Send + 'static,
{
    Box::pin(async move {
        let mut attempt = 0;
        let max = policy.max_attempts.max(1);
        let mut last_err: Option<E> = None;
        // Loop. task.clone() requires the underlying closure to be
        // cloneable; if SkyTask isn't Clone today, wrap in an Arc of
        // the factory closure (see Risks §5.3).
        while attempt < max {
            attempt += 1;
            match task.clone().await {
                SkyResult::Ok(v) => return SkyResult::Ok(v),
                SkyResult::Err(e) => {
                    let should = match &policy.should_retry {
                        ShouldRetry::Always => true,
                        ShouldRetry::When(f) => f(e.clone()),
                    };
                    if !should || attempt >= max {
                        return SkyResult::Err(e);
                    }
                    last_err = Some(e);
                    let delay_ms = compute_delay(
                        policy.kind, policy.base_ms, policy.jitter, attempt,
                    );
                    tokio::time::sleep(
                        std::time::Duration::from_millis(delay_ms as u64),
                    ).await;
                }
            }
        }
        SkyResult::Err(last_err.expect("retry loop exited without err"))
    })
}

fn compute_delay(kind: i64, base_ms: i64, jitter: bool, attempt: i64) -> i64 {
    let raw = match kind {
        0 => base_ms,                                  // linear
        _ => base_ms.saturating_mul(1_i64 << (attempt - 1)),
    };
    let capped = raw.min(30_000);
    if jitter {
        let factor = 0.5 + rand::random::<f64>(); // [0.5, 1.5)
        ((capped as f64) * factor) as i64
    } else {
        capped
    }
}
```

The `Arc<dyn Fn(E) -> bool + Send + Sync>` inside the `When` variant is **not** type erasure of an unknown thing — it's the well-defined function-pointer slot of the ADT, statically known to be exactly that shape. Rust's standard library uses the same pattern for `Box<dyn Fn>` in `std::thread::spawn`; nobody calls that runtime type erasure.

### 3.5 AEAD crypto kernels

**File:** `runtime-rust/src/sky_runtime/crypto.rs` (additions, ~250 LOC)

**Dependencies (Cargo.toml additions):**

```toml
aes-gcm           = { version = "0.10", optional = true }
chacha20poly1305  = { version = "0.10", optional = true }
pbkdf2            = { version = "0.12", optional = true, features = ["simple"] }
```

Add to `crypto` feature: `crypto = ["sha2", "rsa", "bcrypt", "aes-gcm", "chacha20poly1305", "pbkdf2"]`.

**Kernels (8 of them, mirroring `runtime-go/rt/crypto_aead.go`):**

| Kernel | Sky sig | Backing crate |
|---|---|---|
| `aes256gcm_encrypt` | `Bytes -> Bytes -> Result Error Bytes` | `aes-gcm::Aes256Gcm` |
| `aes256gcm_decrypt` | `Bytes -> Bytes -> Result Error Bytes` | same |
| `chacha20poly1305_encrypt` | `Bytes -> Bytes -> Result Error Bytes` | `chacha20poly1305::ChaCha20Poly1305` |
| `chacha20poly1305_decrypt` | `Bytes -> Bytes -> Result Error Bytes` | same |
| `aes_key_from_password` | `String -> Bytes -> Result Error Bytes` | `pbkdf2-hmac-sha256`, 100k iter, 32-byte out |
| `chacha_key_from_password` | `String -> Bytes -> Result Error Bytes` | same |

**Behavioural contract (matches Go runtime):**

- Per-call nonce drawn from `rand_core::OsRng` (cryptographically secure).
- Encrypting the same plaintext twice yields different ciphertexts (nonce is prepended to ciphertext).
- Wrong-length keys → `Err Error` with helpful message ("AES-256-GCM requires a 32-byte key").
- Tampered ciphertexts → `Err Error` from AEAD authentication failure (never silent garbage).
- Wrong keys → `Err Error` from AEAD authentication failure.
- PBKDF2 100 000 iterations (OWASP 2026 floor), 32-byte output, salt provided by caller.

### 3.8 v0.15.43 panic-recover gate — verified no-op

**Upstream change:** `76b8db83 feat(panic-recover): top-level main() recover→Err gate` adds `defer recover()` at the Go runtime's `main()` entry — catches panics and converts them to a top-level `Err Error` rather than crashing the process.

**Rust analogue:** the Rust target's task entry (`task_run` in `runtime-rust/src/sky_runtime/task.rs`) already wraps async execution via tokio's runtime, which surfaces panics through the `JoinError` channel. The existing `safe_async` / `Box::pin(async move { ... })` shape converts panics during async execution to the `SkyResult::Err` channel automatically.

**Verification:** add one new regression test `tests/rust-codegen/panic-during-task.sky` — a Task that panics; assert the top-level returns `Err`, doesn't crash. If this passes (expected: yes), no Rust adaptation needed. If it fails, file as sub-D.2.

## 5. Risks

| Risk | Mitigation |
|---|---|
| `SkyTask` may not be `Clone` today, blocking the retry loop's `task.clone().await` pattern. | If `SkyTask = Pin<Box<dyn Future>>` isn't Clone, wrap the **task factory** instead — store an `Arc<dyn Fn() -> SkyTask<E,A> + Send + Sync>` and call the factory fresh each attempt. Add to the kernel arm: codegen passes a thunk instead of the already-materialised task. Detail-level decision belongs in the plan, not the spec. |
| `Sky.Core.Task` is loaded via embedded TH at runtime; override path must reach the embedded view. | Extend `src/Sky/Build/EmbeddedRuntime.hs`'s TH glob to scan `runtime-rust/sky-stdlib-overrides/` first. The TH source itself is `TargetRust`-agnostic; the override-vs-upstream selection happens at module-load time inside `resolveStdlibPath`, which IS target-gated. |
| The codegen rejection (§3.1) is too aggressive — could block legitimate `any` uses in non-record positions (e.g. function args, ADT payloads) that the Rust target CAN handle via generic instantiation. | The rejection is **scoped to record-field positions only**. `any` in function signatures continues to be a fresh-per-occurrence type variable, same as today, lowered to a generic `T` parameter when possible. The pass walks `Can.TRecord` field types specifically. |
| AEAD crate version drift — `aes-gcm 0.10` may have breaking API changes vs newer. | Pin to `0.10.x` minor in `Cargo.toml`. Bump only on need with regression tests. |
| Upstream may take a long time to accept the ADT redesign — override could live for months. | Acceptable. The override is **one Sky file** in our repo, ~50 lines. Maintenance cost is "re-read it when upstream Task.sky changes" — same cost as any merge conflict, but smaller scope. |
| Future upstream surfaces using `any` in record fields multiply the override surface. | Each one trips the §3.1 diagnostic at codegen time. We decide override-vs-PR per case; the codegen never silently lowers an unsafe shape. |
| The override loader resolves paths from the working directory; running `sky` outside the repo root could break. | The path resolution already walks up to find `sky-stdlib/`; same walk for `runtime-rust/sky-stdlib-overrides/`. If `sky-stdlib/` is resolved (which the current build already requires), the override path resolves correctly. |
| Embedding TH paths are baked into the `sky` binary at build time — installing the binary elsewhere may break override discovery. | Acceptable — the binary already embeds `sky-stdlib/` content via TH for portability. The override path follows the same TH-embedding mechanism. The on-disk path resolution is the secondary fallback for in-repo builds. |

## 7. Upstream issue/PR appendix

To be filed against `anzellai/sky` once sub-D lands locally:

> ### Title
> Proposal: replace `RetryPolicy.shouldRetry : any` with `type ShouldRetry e = RetryAlways | RetryWhen (e -> Bool)`
>
> ### Summary
> The `v0.15.44 part 3` retry surface (`5947cf81`) introduced a record alias with an `any`-typed field whose runtime behavior depends on Go's `interface{}` semantics — the same record value holds a sentinel marker from `linearBackoff` and a closure from `retryOn`. This shape is HM-impure (record-update doesn't preserve a stable concrete type for the field across instances) and can't be lowered to any statically-typed backend without runtime boxing / downcasts.
>
> Concretely on the Rust target: lowering `any` to `Box<dyn Any>` works at runtime but defeats the Rust backend's reason to exist (static dispatch, no type erasure). The arthurmaciel/sky fork's `feat/runtime-rust` branch carries a local override at `runtime-rust/sky-stdlib-overrides/Sky/Core/Task.sky` using an ADT:
>
> ```elm
> type ShouldRetry e = RetryAlways | RetryWhen (e -> Bool)
>
> type alias RetryPolicy e =
>     { maxAttempts : Int, baseMs : Int, kind : Int, jitter : Bool
>     , shouldRetry : ShouldRetry e
>     }
> ```
>
> ### Why this is also better for the Go target
> The Go `task_retry_with` currently does a reflect-backed type assertion on `shouldRetry` per attempt. With the ADT, the same logic becomes a fixed `switch` on the constructor tag — cheaper, simpler, and the compile-time exhaustiveness check covers it.
>
> ### Migration
